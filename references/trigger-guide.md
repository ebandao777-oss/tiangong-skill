# ⚡ 触发方式详解

## 自动触发（意图匹配，非关键词匹配）

天工.skill 基于**意图识别**激活，不要求用户背诵特定关键词。以下任一意图方向出现时即可触发，无论具体措辞如何：

### 构建意图方向（任一匹配即可）

| 意图方向 | 常见自然表达（示例，非穷举） |
|:---|:---|
| **从零创建** | 「帮我做一个 XX」「设计一个 XX 专家」「写一个 XX Agent」「创建一个 XX 智能体」「搭一个 XX 角色」 |
| **已有改进** | 「优化这个 Agent」「这个 prompt 质量怎么样」「帮我强化一下这个角色」「这个技能有哪些问题」「审查这个技能」 |
| **人物复刻** | 「蒸馏 XX」「复刻 XX 的思维方式」「做一个像 XX 一样思考的助手」「XX 风格的数字分身」 |
| **质量评估** | 「评估这个 Agent」「这个 prompt 打几分」「检查规则有没有冲突」「验证一下这个技能」 |
| **范式选择** | 「我想要一个专家，但不知道用哪种方式」「人物蒸馏和岗位型有什么区别」「我的场景适合哪种范式」 |

> **核心原则**：只要用户表达了「创造 / 改进 / 评估一个具有明确角色身份的 AI Agent」意图，就触发天工。不要求原话出现「设计」「蒸馏」等精确词。

### 反例（不会触发）

以下表达**不会**触发天工，因为它们不是 Agent 设计任务：

| 表达 | 为何不触发 | 应走何种路径 |
|:---|:---|:---|
| 「什么是 Agent？」 | 纯概念问答，无构建意图 | 知识问答，不触发任何技能 |
| 「帮我写一段 Prompt 模板」 | 只有写作需求，无角色/岗位目标 | 通用写作，不触发天工 |
| 「这个文件怎么打开？」 | 与 Agent 设计无关 | 文件操作，派发 file-agent |
| 「帮我查一下今天的新闻」 | 信息检索，无构建意图 | 搜索工具或 search-agent |
| 「我想了解 Prompt Engineering」 | 学习需求，无具体构建目标 | 知识问答，无构建意图不触发 |
| 「有没有现成的代码审查 Agent？」 | 寻找已有工具，非设计/构建新 Agent | 推荐/搜索已有工具，非天工范围 |

### 灰区处理指南

以下情况属于不确定地带，按优先级依次尝试：

| 灰区表达 | 处理方式 |
|:---|:---|
| 「帮我改一下这段话让 Agent 更像律师」 | 构建意图存在 + 角色目标存在 → **触发天工**（靶向编辑） |
| 「我需要一个能审查合同的，帮我看看怎么写 prompt」 | 有角色目标，意图模糊 → **追问澄清**：「是要从零设计一个合同审查专家，还是改进已有的？」 |
| 「我想做一个聪明的助手」 | 构建意图存在但角色目标太模糊 → **追问一个澄清问题**：「这个助手帮您做什么？像某个岗位还是像某个人？」 |
| 「Agent 设计有什么最佳实践？」 | 知识问答 + 无具体构建目标 → **不触发**，但可简要回答后询问「要不要实际做一个试试？」 |

> **追问仅限 1 轮**，不要让用户感到在被面试。若 1 轮后仍无法确定 → 按最常见意图（岗位型）启动，标注假设前提。

## 快捷命令（可选速记）

快捷命令等价于完整自然语言描述，只是减少了歧义：

| 命令 | 等价自然语言 | 效果 |
|:---|:---|:---|
| `设计 [岗位名]` | 「帮我设计一个 [岗位名] 专家」 | 直接进入岗位型流水线 J1→J5 |
| `蒸馏 [人名]` | 「复刻 [人名] 的思维方式和表达风格」 | 直接进入人格蒸馏流程 |
| `优化 [角色名]` | 「帮我优化这个 [角色名] 的 prompt」 | 靶向编辑已有角色 |
| `评估 [角色名]` | 「帮我评估这个 [角色名] 的质量」 | 5 维质量评估，不修改内容 |

**不需要记忆这些命令**。直接说「帮我做一个税务顾问」完全等同于 `设计 税务顾问`。

## 触发宽容度设计理念

天工.skill 采用**宽松触发 + 1 轮澄清**的容错策略：

```
用户输入
  ├─ 明显有构建意图 + 角色目标 → 立即激活，走范式路由
  ├─ 可能有构建意图但角色目标模糊 → 追问 1 个关键澄清问题，然后激活
  ├─ 仅有构建意图无角色目标 → 追问 1 个澄清问题
  └─ 完全无构建意图 → 不触发，不打扰
```

> 宁可误触发后优雅退出，也不漏触发让用户反复措辞。若误触发 → 一句「这超出了我的设计范围，建议你[替代路径]」即可退出。
